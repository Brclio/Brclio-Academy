# 验证与交付检查

这份文档把代码验证、本地浏览器验收与真实服务验收分开记录。执行命令后保存实际结果；没有运行的项目保留为待验收。

## 1. 代码和构建

在项目根目录执行：

```bash
npm ci
npm run typecheck
npm test
npm run build
node scripts/audit-client.mjs
```

内容完整性测试在 `tests/content.test.ts`，会检查：

- 用户提供的 AI 课程保持 6 章、17 节、19 段视频，视频分组与顺序完全一致。
- 全部课程、章节、课时、文章和专栏的 ID 不重复，文章归属存在。
- 新库没有默认用户、会话、验证码或学习记录。
- 另外三门示例课有实际图文内容和练习，没有虚构视频。
- 每次初始化都返回独立数据，修改一个数据库不会污染后续初始化。

`tests/backend.test.ts` 检查 SQLite 事务与持久化、GitHub SHA 冲突重试和私有仓库约束、加密防篡改、验证码、注册与找回密码、VIP 过期和撤销、用户数据隔离、发布状态、输入限制、运维 CLI 和加密恢复。模拟 GitHub 响应的测试不代表远端仓库已经写入成功。

## 2. 客户端资源泄露检查

`node scripts/audit-client.mjs` 会递归检查 `.next/static/` 中浏览器可下载的 JavaScript、source map 和 JSON，搜索全部 19 个示例视频 ID，以及 GitHub、加密、SMTP 和 Resend 凭证变量名。如果发现匹配或没有构建产物，命令以非零状态退出。

这些视频 ID 只应存在于服务端 seed 和受权限保护的运行时响应中，不应被编译进公共浏览器包。源码中的用户提供示例对拥有源码访问权的人可见；正式保密课程必须在后台录入私有数据存储。

静态字符串检查是回归检查，不是完整的安全证明。还应结合接口测试验证：游客请求课时返回 401，普通用户返回 403，有效 VIP 返回课时；公共目录没有 `content`、`videos` 或 `resources`。生产凭证不得使用 `NEXT_PUBLIC_` 前缀，也不应被手工写进客户端文件。

## 3. 生产构建启动

```bash
npm run build
npm start
```

`npm start` 运行 `scripts/start.mjs`：检查 standalone 构建，复制 `public` 和 `.next/static`，从项目根目录加载生产环境变量，将相对 `SQLITE_PATH` 转为绝对路径，然后启动生成的服务器。这样运行位置不会让应用意外创建另一份数据库。

生产配置须有规范 `APP_URL` 与真实邮件服务。生产模式禁止 console 邮件；只验证开发邮件流程时请使用 `npm run dev`。没有生产构建时，启动脚本应明确提示先运行 `npm run build`。

Docker 与 systemd 直接启动同一个 standalone 入口；相关静态文件复制和持久化路径在 [部署教程](DEPLOYMENT.md) 中列出。

## 4. 本地浏览器验收

使用独立测试数据，避免把演练账号写入正式用户库。

1. 游客浏览首页、课程目录、章节目录、文章与专栏；打开课程正文应被引导登录，VIP 文章正文不可见。
2. 注册新邮箱，输入错误验证码验证错误反馈，再使用正确验证码注册；重复使用旧验证码应失败。
3. 普通用户登录后可以收藏课程，学习入口说明需要管理员开通 VIP。刷新后收藏仍然存在。
4. 管理员搜索该用户，设置未来 VIP 截止时间。学员刷新后进入课程，查看图文内容或播放器。
5. 在多视频课时切换片段，保存进度与笔记，标记完成，再取消完成；刷新后每个状态与最后一次操作一致。
6. 在学习中心确认最近学习、完成数量与个人笔记；使用另一账号验证不能读取前一个账号的记录。
7. 管理员撤销 VIP；学员下一次受保护请求被拒绝。学习记录保留，重新开通后可以继续。
8. 管理员新建图文课程、添加章节课时、调整顺序并保存；发布后目录可见，下架后不可继续读取正文。对文章和专栏重复相同检查。
9. 使用找回密码流程设置新密码，旧会话和旧密码失效；新密码可以登录。
10. 在手机宽度、桌面宽度和键盘操作下检查登录表单、课程目录、学习页与后台，没有横向溢出或无法操作的控件。

账户页目前展示昵称、邮箱、注册时间、角色和 VIP 状态；修改密码通过邮箱找回流程完成。它不提供修改邮箱或昵称的接口。管理员可在后台编辑课程正文，但管理员角色本身不授予课程学习 VIP。

## 5. 真实服务验收

部署后还需要实际完成：

- SMTP 或 Resend 在指定收件箱收到验证码，验证发件人、内容、有效期与失败反馈。
- 逐一打开 19 段 YouTube 视频，检查是否允许嵌入、是否为 Unlisted，以及账号、年龄、地区和实际网络环境限制。
- GitHub 驱动在选定私有仓库中完成真实读写，确认加密文件无可读业务正文。
- 正式 HTTPS 域名登录、退出、注册与后台操作；核对 `APP_URL` 和可信代理配置。
- 导出加密备份，在隔离环境恢复，确认用户、课程、VIP、笔记和进度，同时确认旧会话已清除。
