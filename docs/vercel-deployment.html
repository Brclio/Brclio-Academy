01
Before you deploy

先分清楚，
两个仓库。

Vercel 运行网站；GitHub 私有数据仓库存放加密业务数据；Gmail 发出验证码。三者各有职责。

A

代码仓库：交给 Vercel 构建

Brclio / Brclio-Academy ↗

里面有 package.json、package-lock.json、src/ 和 scripts/。在 Vercel 新建项目时，选择的就是这个仓库。确保准备发布的代码已在 GitHub 上。

B

数据仓库：始终保持 Private

Brclio / academy-private-data ↗

用户、权限、课程、笔记与进度会加密保存为 academy.enc.json。该仓库已有初始提交与 main 分支；首次真正写入数据时，应用才会创建加密文件。不需要手动创建空文件。

C

核对 PAT 与发信邮箱

Fine-grained PAT 的 Resource owner 为 Brclio，Repository access 仅选 academy-private-data，Repository permissions 中 Contents = Read and write；Metadata 保持必需读取权限。组织若要求批准，令牌需获批后才能正常访问。

Gmail 使用 huangwantangbaby@gmail.com 和 应用专用密码。邮箱开启两步验证后，按 Google 账户可用的选项管理应用密码；填写时去掉显示用空格。网站管理员登录密码需要另设。

2026-09-16 预检快照
私有仓库和 main 分支可读取；加密数据文件尚未创建；SMTP 连接与认证检查成功。尚未执行远端写入、发送真实邮件或绑定域名，完整验收在后面进行。

03 / Deploy on Vercel

导入代码，然后导入环境变量。

登录 Vercel 后，选择准备承载学院的账户或团队。下面的字段以当前控制台为准；无需购买域名或新增数据库服务。

  1. New Project → Import Git Repository

    点击 Add New… → Project，连接 GitHub，找到 Brclio/Brclio-Academy 后点击 Import。若列表找不到，调整 Vercel GitHub 集成对应用仓库的访问授权；数据仓库无需导入 Vercel。

  2. 核对右侧构建设置

    Framework Preset 选 Next.js。Root Directory 保持项目根目录，界面通常显示 ./。如果导入时未显示 Node.js 版本，创建项目后到 Settings → Build and Deployment 核对 24.x。

  3. 选择 Import .env，上传本地文件

    展开 Environment Variables，使用 Import .env，选择根目录的 .env.vercel.production。如果导入入口在项目设置中，打开 Settings → Environment Variables 操作；先失败的初次构建可在配置完成后重新部署。

    逐项核对导入后值、引号解析与环境范围，只保留 Production。不要勾选 Preview 和 Development。若文件选择器限定 .env，可以在电脑上复制为临时 .env 文件再导入，完成后妥善移除临时副本。

  4. Deploy → 等待 Ready

    点击 Deploy，在 Build Logs 查看依赖安装与构建结果，等待状态变为 Ready。需要修改变量时，保存后从 Deployments → 生产部署 → ⋯ → Redeploy 再部署一次；修改不会自动更新已有部署。

04 / Your domain

把正式入口，
指向 academy.brclio.com。

APP_URL 已预填正式域名。接下来需要在 Vercel 添加域名，并按它给出的实际 DNS 提示完成解析。

  1. 项目 Settings → Domains，添加 academy.brclio.com，关联 Production 环境。
  2. 到域名实际使用的 DNS 服务商，按 Vercel 展示的记录类型、名称与目标添加记录。子域通常用 CNAME，但以控制台给出的当前值为准。
  3. 回到 Vercel 等待 Valid Configuration，确认 HTTPS 证书可用。若要求所有权验证，再按提示添加对应 TXT 记录。
  4. 访问正式域名，确认浏览器地址与 APP_URL 完全一致。只要修改过 APP_URL，就保存并 Redeploy。

如果先在 *.vercel.app 测试：临时将 APP_URL 改成那个确切的 HTTPS 地址并 Redeploy；正式域名可用后切回 https://academy.brclio.com，再 Redeploy。注册、登录、后台统一从同一地址进入。

地址核对小助手

输入将要访问的站点，生成对应 APP_URL。这里只做本地格式检查，不检查 DNS，也不会修改环境文件。

APP_URL=https://academy.brclio.com格式正确；域名绑定与 HTTPS 需在 Vercel 验证。

不要填 /login、/admin、参数或邮箱密码。这里需要的是网站的 origin：协议 + 域名。

05 / First administrator

回到电脑，
创建你的管理员。

下面的命令由你在本地项目根目录执行，会真实写入私有数据仓库。它明确加载本次生产文件，不会误用开发用的 .env.local。先安装 Node.js 24.x 与依赖 npm ci。

本地终端 · 在 Brclio-Academy 根目录运行
bash -c '
set -e
read -r -s -p "设置网站管理员密码（10–128 位，输入不显示）：" ADMIN_PASSWORD
printf "\n"
export ADMIN_PASSWORD
node --env-file=.env.vercel.production --import tsx scripts/admin.ts --email huangwantangbaby@gmail.com --name Brclio
'
这是学院网站的独立密码
输入时终端不会显示字符，这是正常现象。不要输入 Gmail 应用专用密码或 GitHub 令牌。使用 10–128 位的独立密码并妥善保存；Bash 子进程结束后变量随之清理。

第一次创建成功后

终端会提示管理员已创建。仓库 main 中出现 academy.enc.json，内容为加密数据。访问 https://academy.brclio.com/login，使用上面的邮箱和刚设的学院密码登录，再打开 /admin。

管理员权限和 VIP 学习权限互相独立。需要自己试学时，在后台为自己的账号设置未来的 VIP 截止时间。

如果邮箱已经注册并验证

创建命令会拒绝覆盖现有账号。确认该账号已完成邮箱验证后，可以提升角色，保留原来的登录密码：

node --env-file=.env.vercel.production --import tsx scripts/admin.ts   --email huangwantangbaby@gmail.com --promote

07 / Troubleshooting

遇到问题，
按现象找原因。

先看 Vercel 的构建日志或 Functions / Runtime Logs，定位报错发生在构建、发信、数据访问还是登录请求。分享日志时隐藏真实凭证。

页面能打开，但提示“来源校验失败”
核对地址栏的协议与域名是否等于 Production 的 APP_URL。常见情况是环境中写 academy.brclio.com，却从 *.vercel.app 登录。统一地址后保存变量并 Redeploy，再刷新页面重试。
GitHub 返回 401、403 或 404
401 常见于令牌过期或错误；403 检查 Contents 读写、组织批准、组织令牌政策与 API 限流；404 同时检查 owner、repo、分支和令牌授权。私有仓库缺少授权也可能表现为 404。未初始化前 academy.enc.json 不存在是正常的，但仓库与 main 分支必须存在。
SMTP 登录成功，为什么还收不到验证码？
连接检查只确认认证，不证明邮件已经投递。正式流程需真实点击发送验证码，再检查收件箱、垃圾邮件和 Vercel 运行日志。配置为 smtp.gmail.com / 465 / true，MAIL_FROM 与 SMTP_USER 一致。确认 SMTP_PASS 是有效应用密码；Google 账户密码变更可能撤销应用密码。重复发送受至少 60 秒间隔限制。
找不到 .env 文件，或导入后变量未生效
macOS 的文件选择器按 ⌘⇧. 显示隐藏文件。核对文件位于项目根目录、导入后的环境范围为 Production、值里没有意外引号或空格，然后 Redeploy。自定义文件名 .env.vercel.production 不会由 Next.js 自动加载；本地管理员命令必须保留 --env-file 参数。
构建末尾找不到 next-server.js.nft.json
这是 Next.js 16.3 的构建适配器与 standalone 输出兼容问题。项目已改为 output: process.env.VERCEL ? undefined : 'standalone'：Vercel 使用默认输出，本地和 Docker 保留 standalone。请部署包含修复的新代码提交；重复部署旧提交不会应用本地改动。无需修改 env 或手工创建空的追踪清单。查看 Next.js 问题记录 ↗
其他构建失败，或提示 SQLite 不适用于 Vercel
检查是否选了应用代码仓库、根目录是否含 package.json、Node 是否为 24.x、Install Command 是否为 npm ci、Build Command 是否为 npm run build。package.json 和锁文件已经固定 Node 24.x。缺少环境变量或仍使用 sqlite 时，将 Production 的 DATA_DRIVER 设为 github 并导入完整配置。输出目录保持 Next.js 默认。
出现“无法解密”或数据突然无法读取
使用最初创建数据的 DATA_ENCRYPTION_KEY。不要通过删除数据文件或随机换新密钥“修复”。先停止继续写入，核对本地备份与 Vercel 中的密钥是否一致；迁移与换密钥应按项目备份恢复步骤操作并保留回退副本。
管理员能进后台，却不能学习课程
管理员角色不自动授予 VIP。到后台为自己的账号设置未来的 VIP 截止时间。视频问题还要逐个核对是否允许嵌入、可访问性与网络条件；部署 Ready 不代表所有视频都能播放。
首次管理员命令报“账号已存在”
脚本不会覆盖原账号和密码。该邮箱已完成验证时，使用本页的 --promote 命令提升权限，再用原网站密码登录。不要把 Gmail 应用密码当作网站密码；需要重置时使用网站的忘记密码流程。
